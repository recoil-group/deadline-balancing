# Deadline balancing guide

This document describes how to reason about balance changes. See [stats.md](stats.md) for stat behavior and units. The root CSVs remain authoritative for the values they define.

## Goals

Balance work should support four goals:

- **Fairness:** no option should dominate its alternatives without a meaningful cost.
- **Variety:** options should create distinct strengths, weaknesses, and use cases.
- **Realism:** real equipment should be the starting point for relative performance.
- **Aesthetics:** realistic and visually coherent builds should be encouraged.
